# LendLoop Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Build the LendLoop take-home (tool-lending board + 2 n8n workflows) so every brief requirement is met and verified.

**Architecture:** Next.js App Router UI talks to Convex (cloud dev deployment) through the Convex React client authenticated by Clerk. All authorization lives in Convex functions. Convex → n8n via an outbox + scheduled action that POSTs HMAC-signed payloads through a Cloudflare Quick Tunnel; n8n → Convex via signed calls to Convex HTTP actions. n8n and Mailpit run in docker-compose.

**Tech Stack:** Next.js (App Router) + TypeScript + Tailwind, Clerk (`@clerk/nextjs`), Convex (`convex`, `convex-test`), Vitest + `@edge-runtime/vm`, n8n (Docker), Mailpit (Docker), cloudflared, pnpm, Node 24.

**Spec:** `docs/superpowers/specs/2026-11-08-lendloop-design.md` (read it; this plan does not repeat its rationale).

## Global Constraints

- Code, comments, commits, README in English. Commit messages end with `Co-Authored-By: Claude Opus 5.5 <noreply@anthropic.com>`.
- pnpm, exact versions (`.npmrc`: `save-exact=true`). Free tiers only — stop and tell Enzo if anything asks for payment.
- Never create accounts or handle passwords. When a key is needed, ask Enzo to paste it into `.env.local` (gitignored).
- Before every commit: `pnpm check:secrets` (Task 1) must pass; inspect any `n8n/workflows/*.json` being committed.
- Loan dates are `"YYYY-MM-DD"` strings in UTC. Timestamps are ms numbers.
- HMAC canonical string: `` `${timestamp}.${METHOD}.${path}.${rawBody}` ``; headers `X-LendLoop-Timestamp` (unix seconds) and `X-LendLoop-Signature` (lowercase hex HMAC-SHA256); tolerance 300 s.
- Secrets: `LENDLOOP_TO_N8N_SECRET` (Convex signs, n8n verifies), `N8N_TO_LENDLOOP_SECRET` (n8n signs, Convex verifies).
- Idempotency keys: `notify:{eventId}`, `reminder:{loanId}:{YYYY-MM-DD}`, `error:{executionId}`. eventId = `loan:{loanId}:{status}:{updatedAt}`.
- Outbox retry backoff: 1 min, 5 min, 30 min; after 4 total attempts → `failed`.
- Limits: tool name ≤ 80 chars, description ≤ 500, ≤ 50 tools per user, ≤ 10 `requested` loans per borrower, HTTP body ≤ 16 KB.
- Categories: `power_tools | hand_tools | garden | kitchen | camping | cleaning | other`. Conditions: `new | good | fair | worn`.
- Tagline: "Borrow what you need. Lend what you don't." CTA: "Sign in to lend or borrow".
- AWS / HIPAA / ISO appear only as production plans, never as experience or compliance claims.
- Keep code simple and readable: obvious names, few abstractions, comments only for the why.

## Review Focus

1. **End date = today is not overdue**; overdue starts the day after `endDate` (UTC). → test in Task 2 (`dates.test.ts`).
2. **Two overlapping requests approved back-to-back** → second approve must throw (and the first approve already auto-declined it). → test in Task 4.
3. **Body re-serialization breaks signatures**: verifiers must hash the raw body text, never `JSON.stringify(JSON.parse(body))`. → test in Task 6 (whitespace-changed body fails) and n8n Webhook "Raw Body" option in Task 10.
4. **Signed-in user whose `users.store` has not run yet** calls a mutation → clear "User not registered" error, not a crash; UI waits for store before rendering signed-in views. → test in Task 2, UI gate in Task 5.
5. **Stale tunnel URL / n8n down** → outbox row ends `failed` with `lastError` visible in `/admin`, never silent. → test in Task 7, manual check in Task 16.
